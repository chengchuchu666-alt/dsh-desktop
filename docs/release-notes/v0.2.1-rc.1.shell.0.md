# dsh-desktop v0.2.1-rc.1.shell.0

> 发布说明随 tag 固定；公开下载与校验以实际 Release 和官网为准。

DeepSeek Harness 社区桌面版 · 内置内核 `@deepseek-ai/dsh` `0.2.1-rc.1`。

## 本次更新

- **内核升级**：把内置 Harness 从 alpha.5 升到 `0.2.1-rc.1`（上游 `next` 通道），同步 32 个
  内核同族直接依赖、锁文件与 `minimumReleaseAgeExclude`。上游随后发布了
  [官方预览版说明](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-rc.1)
  （2026-10-17T05:22Z）。
- **说明口径**：上游 rc.1 说明汇总的是 `v0.2.0-rc.2` 以来的整条 0.2.1 变更线，其中多数已随
  alpha.1–alpha.5 进入本壳此前的版本；就 alpha.5 → rc.1 这一段，逐包 registry 元数据核对显示
  297 个内核包仅有版本字符串一类的小幅缩减。本壳的实际使用面（会话控制器、工作区客户端、
  账户登录补丁、ACP 组合）在 rc.1 未发生变化。
- **闭包差异**：按 registry 元数据逐包比对，297 个内核包全部只有版本字符串一类的小幅缩减
  （每个包 −100～−500 字节，来自 `0.2.1-alpha.5` → `0.2.1-rc.1` 的替换），没有新增或移除依赖；
  壳直接打补丁或依赖契约的三个包中，`dsh-api-session-controller` 与 `dsh-client-ui-workspace`
  逐字节一致，`dsh-client-ui-settings-account` 仅两处版本字符串变化，ACP/headless 的
  `cordis.patch.yml` 组合未变。
- **上游移除/变更接口核对**：rc.1 移除了运行时 invariant 插件与各包 `./invariant` 导出、工具展示的
  `both` 混合模式、输入区 `stats` 统计行，并把 `--from-default-profile` 调整为替换式重建，
  Agent Team 消息改为直接投递 Inbox。全仓检索确认本壳未使用其中任何接口：没有
  `from-default-profile` 调用，没有 invariant 引用，没有注册 `stats` 行，也没有使用 `both` 模式；
  本壳的 ACP 与凭据边界（Web/桌面优先已保存凭据、headless 改用环境变量）与既有断言一致。
- **插件框架转正**：内核声明的 cordis 家族在同一批次由 `-alpha.2` 预发布转为稳定版
  （`@deepseek-ai/cordis` 4.0.5、`cordis-plugin-include` 1.0.10、`cordis-plugin-loader` 1.0.6、
  `cordis-plugin-timer` 1.1.7，以及 `cosmokit`/`schemastery` 同线更新），稳定版发布时间早于
  rc.1，属于内核自身声明的范围解析结果，不是本壳额外引入的依赖。
- **账户登录兼容**：账户补丁随精确版本迁移到 rc.1，补丁内容不变，继续只在官方桌面桥具备
  `dshOnboarding.hasApiKey` 能力时走内嵌登录；Electron 拒绝预开空白窗口时仍把实际授权 URL
  一次性交给系统浏览器，不放开导航、Node 权限或外链协议。
- **垃圾桶兼容**：会话控制器与工作区客户端与 alpha.5 逐字节一致，补丁锚点重新核对后版本保护
  更新为 rc.1；运行中、排队中、跨客户端所有权、维护中及子会话仍拒绝删除。
- **构建可复现性**：`pnpm run bootstrap` 现在固定使用仓库锁定的 pnpm 10.33.2 生成/校验锁文件，
  并显式请求 hoisted 布局，不再依赖外层 pnpm 注入的环境；此前用 pnpm 11 写出的紧凑
  `patchedDependencies` 形式会被 10.33.2 判为配置不匹配，导致 bootstrap 在
  `ERR_PNPM_LOCKFILE_CONFIG_MISMATCH` 处中止。
- **飞书快捷控制**：浮窗「连接」分组继续分开显示当前应用、桌面进程、飞书通道与 DSH 任务，
  并提供显式开启、关闭、重连；打开或轮询只读，不隐式连接、不发消息、不调用模型。

## English Summary
- **Kernel upgrade**: the bundled Harness moves from alpha.5 to `0.2.1-rc.1` (upstream `next` channel) with 32
  kernel-family direct dependencies, the lockfile and `minimumReleaseAgeExclude` re-synced; upstream published its
  [preview notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-rc.1) at 2026-10-17T05:22Z.
- **Scope of those notes**: they summarize the whole 0.2.1 line since `v0.2.0-rc.2`, most of which already reached
  this shell in alpha.1–alpha.5. For the alpha.5 → rc.1 step, per-package registry metadata shows 297 kernel
  packages changed only in version strings, and the surfaces this shell actually uses (session controller,
  workspace client, account patch, ACP composition) are unchanged in rc.1.
- **Closure diff**: all 297 kernel packages shrink by 100–500 bytes each from the `0.2.1-alpha.5` → `0.2.1-rc.1`
  substitution with no dependency added or removed; of the three packages this shell patches or depends on by
  contract, `dsh-api-session-controller` and `dsh-client-ui-workspace` are byte-identical,
  `dsh-client-ui-settings-account` differs only in two version strings, and the ACP/headless `cordis.patch.yml`
  composition is unchanged.
- **Removed or changed upstream interfaces audited**: rc.1 drops the runtime invariant plugin and each package's
  `./invariant` export, the `both` tool-display mode and the input-area `stats` row, turns `--from-default-profile`
  into a replace-style rebuild, and delivers Agent Team messages straight to the Inbox. A repository-wide search
  confirms this shell uses none of them (no `from-default-profile` call, no invariant reference, no `stats` row, no
  `both` mode), and its ACP and credential boundaries still match the existing assertions.
- **Plugin framework promoted**: the cordis family the kernel declares moved from `-alpha.2` prereleases to stable
  releases in the same batch (`@deepseek-ai/cordis` 4.0.5, `cordis-plugin-include` 1.0.10,
  `cordis-plugin-loader` 1.0.6, `cordis-plugin-timer` 1.1.7, plus same-line `cosmokit`/`schemastery` updates);
  those stable releases predate rc.1, so this is the kernel's own resolution rather than a dependency this shell
  added.
- **Account-login compatibility**: the account patch moved to rc.1 unchanged and still uses the embedded login only
  when the official desktop bridge exposes `dshOnboarding.hasApiKey`; when Electron refuses a pre-opened blank
  window it hands the real authorization URL to the system browser once, without opening up navigation, Node
  privileges or external protocols.
- **Trash compatibility**: the session controller and workspace client are byte-identical to alpha.5 and the version
  guard now targets rc.1 after re-checking the anchors; running, queued, cross-client-owned, maintenance and child
  sessions still refuse deletion.
- **Reproducible builds**: `pnpm run bootstrap` now always generates and validates the lockfile with the
  repository-pinned pnpm 10.33.2 and explicitly requests the hoisted layout instead of inheriting the caller's pnpm
  environment; the compact `patchedDependencies` form written by pnpm 11 is rejected by 10.33.2 as a configuration
  mismatch and used to abort bootstrap with `ERR_PNPM_LOCKFILE_CONFIG_MISMATCH`.
- **Feishu quick control**: the floating panel's Connect group keeps application, desktop process, Feishu channel
  and DSH-task states separate with explicit start, stop and reconnect; opening or polling it is read-only and never
  connects, sends a message or calls a model.
