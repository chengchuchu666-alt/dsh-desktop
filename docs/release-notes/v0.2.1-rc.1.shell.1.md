# dsh-desktop v0.2.1-rc.1.shell.1

> 发布说明随 tag 固定；公开下载与校验以实际 Release 和官网为准。

DeepSeek Harness 社区桌面版 · 内置内核 `@deepseek-ai/dsh` `0.2.1-rc.1`（未变，壳修订 +1）。

## 本次更新

- **插件崩溃后能自愈（#115 一类）**：当某个加载行引用了内置内核不提供的包时，以前只有
  "启动失败"和一个反复重启的循环——安全模式也救不回来（安全模式只收集用户 bundle 插入的行，
  而失败行常常来自 `cordis.patch.yml` 或它 include 的文件）。本版：失败分类新增"找不到包"，
  错误页直接给出"升级到最新版 / 禁用该插件"的方向；安全模式开始覆盖 profile 与 home 两层的
  `cordis.patch.yml` 及其 `include` 文件（用户对**官方行**的配置覆盖仍保持启用，不会被误禁用）；
  自动隔离不再只认 bundle 名，非 bundle 的失败行会被记入壳自有的禁用 overlay，下次启动自动
  绕开它，并可在错误页、「桌面工具」菜单或升级/禁用该插件后一键解除。
- **profile 文件不可写不再死循环（#100/#116）**：内置内核每次启动都会重写
  `profiles/web/cordis.yml`，该文件只读、ACL 拒绝写入或被 Windows"受控文件夹访问"拦截时，
  以前表现为"白屏后怎么重启都起不来"，而体检仍显示"数据目录可写"。本版在启动前做**文件级**
  写权限预检：预检失败不再空转重启，而是给出带具体路径的错误页与"修复文件权限并重启"按钮
  （清除只读属性后自动重试）；体检的"数据目录与磁盘"项改用同一探测；诊断报告新增
  `profile_write=` 一行。
- **白屏可诊断（#100）**：渲染进程没有崩溃但页面空白时，以前没有任何线索，只能请用户手工开
  开发者工具。本版采集渲染进程的 error/warning 控制台消息与"无响应"事件（环形缓冲、限长、
  导出时脱敏），写入诊断报告的 `renderer_errors` 段；渲染进程恢复失败时也会把首条异常并入
  错误页日志尾部。
- **诊断更完整**：插件清单新增 `patch_layers`（读到的用户补丁层）与 `unkeyed_rows`
  （无法按 id 禁用的"隐形行"）——以前这两类信息在报告里完全看不到。
- **内核未变**：仍打包 `@deepseek-ai/dsh` `0.2.1-rc.1`，只递增壳修订号；上游 `0.2.1-rc.2`
  不在本次范围内，不借壳发布做隐式内核升级。
- **边界说明**：所有修复都在本机完成，不改变隐私边界——诊断报告仍只在本地生成、不自动上传；
  一键修复只清除只读属性，不修改 ACL、不调整安全软件设置、不删除用户数据。

## English Summary

- **Plugin crashes now self-heal (#115 family)**: a loader row that imports a package the bundled
  kernel does not carry used to leave only "startup failed" and a restart loop — Safe Mode could not
  help because it only collected rows inserted by user bundles, while the failing row usually comes
  from `cordis.patch.yml` or a file it includes. This release classifies that failure as
  `missing-package`, points the error page at the fix (update the app or disable the plugin), extends
  Safe Mode over the profile/home patch layers and their includes (user overrides of *official* rows
  stay enabled), and records non-bundle failing rows in a shell-owned quarantine overlay that skips
  them on the next start — reversible from the error page, the extensions menu, or by updating or
  disabling the plugin.
- **An unwritable profile no longer loops (#100/#116)**: the kernel rewrites
  `profiles/web/cordis.yml` on every start, so a read-only file (or an ACL/Controlled Folder Access
  block) used to look like "blank screen, then it never starts again" while the health check still
  reported the data folder as writable. The shell now probes the profile *files* before spawning,
  refuses to spin on a doomed boot, and shows a page with the concrete path and a one-click
  "repair file permissions and restart" action; the storage health check uses the same probe and the
  diagnostic report gained a `profile_write=` line.
- **Blank renderers are diagnosable (#100)**: renderer console errors/warnings and unresponsive
  events are captured into a bounded, redacted `renderer_errors` section of the diagnostic report,
  and the renderer-failure page now carries the first exception.
- **More complete diagnostics**: the plugin inventory reports `patch_layers` and `unkeyed_rows`.
- The bundled kernel is unchanged at `@deepseek-ai/dsh` `0.2.1-rc.1`; only the shell revision moves,
  so upstream `0.2.1-rc.2` is deliberately not pulled in by a shell release.
- Everything stays local-first: the diagnostic report is still generated on-device and never
  uploaded automatically, and the repair only clears the read-only attribute — it does not touch
  ACLs, security-software settings, or user data.
