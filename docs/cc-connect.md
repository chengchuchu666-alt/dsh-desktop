# cc-connect × DSH Desktop 使用指南

本页说明如何在 dsh-desktop 中启用内置的 cc-connect 飞书连接。cc-connect
作为由 Electron 主进程监管的 Sidecar 运行，通过 DSH 官方 ACP stdio 协议
启动 `dsh --profile acp`；它不复制 Harness 的会话模型，也不读取 Web 页面内部
接口。飞书使用 WebSocket 长连接，因此本机不需要公网 IP、域名或反向代理。

## 开始前

- 使用包含 cc-connect 的 dsh-desktop 安装包，并准备一个已经存在的绝对路径工作区。
- 准备一个有权限发布应用版本的飞书或 Lark 开放平台账号。
- 默认扫码创建，无需手抄 App Secret；已有应用的 Secret 只在管理窗口一次性输入，不要写入仓库、截图、Issue 或日志。

## 飞书开放平台配置

1. 打开[飞书开放平台](https://open.feishu.cn/)，创建企业自建应用。
2. 在「应用能力」中启用「机器人」能力。
3. 在「凭据与基础信息」中记下 App ID 和 App Secret。
4. 在「权限管理」中按组织审批要求申请消息读取和发送权限。通常至少需要：
   `im:message:send_as_bot`、单聊消息读取权限，以及群聊中接收机器人消息的权限
   （控制台名称可能随飞书/Lark 版本变化）。需要读取未 @ 机器人的群消息时，另外申请
   `im:message.group_msg`；Desktop 的固定配置默认不会启用这项历史共享功能。
5. 在「事件与回调」中选择「使用长连接接收事件」，添加事件
   `im.message.receive_v1`。
6. 如果要使用交互卡片上的权限确认等按钮，再添加回调
   `card.action.trigger`。没有该回调时，普通文本消息仍可连接，但卡片按钮不能完成回调。
7. 创建并发布应用版本，确认应用的可用范围包含要使用机器人聊天的账号或群组。
   然后把机器人加入目标单聊或群聊。

飞书控制台的权限名称和菜单可能会调整；以当前控制台显示的应用权限、事件和发布状态
为准。cc-connect 的更详细平台说明见子模块的 `docs/feishu.md`。

## 在 Desktop 中启动和停止

### 默认入口：管理应用／扫码创建

从 `v0.2.1-alpha.3.shell.0` 起，支持「设置 → 飞书连接」和桌面工具浮窗的「连接 → 飞书连接」入口。
原有「设置 → 桌面设置 → 飞书消息连接 → 管理应用／扫码创建」、原生菜单
「扩展 / Desktop tools → 管理飞书连接…」继续保留。所有入口打开同一个管理窗口，旧版
「配置飞书机器人」入口已演进为应用管理；不要求安装全局 CLI。

1. 填本地名称，选择已经存在的绝对路径工作区，点击「生成二维码」。
2. Desktop 在隔离临时目录启动捆绑 cc-connect，显示二维码、授权等待剩余时间与进度。
3. 用手机飞书扫码并确认；手机显示“应用成功”不等于 Desktop 已收到凭据。等待窗口显示
   「应用已保存」，并出现已保存应用卡片。超时可重新生成，取消会清理临时目录和进程。
4. 点击该应用的「开启连接」。扫码保存不会隐式切换当前应用，也不会自动发测试消息。

保存、取消或超时后会清理临时凭据。创建中关闭窗口等同取消；若凭据已进入原子保存阶段，
保存可完成，但不会自动开启。关闭管理窗口不会关闭已经运行的连接。

已保存列表支持命名、编辑工作区和显示偏好、替换 Secret、开启另一份应用、确认移除本地配置。
一次只连接一份应用；切换必须先等待旧进程退出，停止失败不会开启第二个。新应用的聊天
运行数据相互隔离；旧连接迁移保留原聊天数据目录。

### 设置页配置和生命周期

打开「设置 → 桌面设置 → 飞书消息连接」：

默认使用「管理应用／扫码创建」。已有机器人在管理窗口展开「已有应用（高级）」，填写
App ID、App Secret、名称和工作区，点击「保存应用」或明确标注的「保存并开启连接」。
设置页的「高级：当前应用配置」保留旧配置入口，只修改选中应用，不覆盖另一份应用。

状态分三层：**桌面服务已启动**只证明进程初始化；**飞书通道在线**来自官方 SDK 连接回调；
**DSH 已成功完成任务**只有实际 ACP turn 成功后出现。未收到对应信号显示尚未确认／尚未
通过任务验证，不把手机扫码、CLI OAuth 或进程 ready 显示成已验证收发。
缺模型 API key 时去主窗口 **Models** 页面通过 credentials 服务保存，不能填到机器人 Secret。
权限/发布失败检查飞书后台，网络错误检查代理与网络，工作区失效重新选择目录。

Secret 输入框是一次性写入框：保存成功后会自动清空；之后保存时留空表示保留已经保存的
Secret，不会把它清掉。界面只显示“Secret 已保存”及存储保护类型，不会读回 Secret。

#### 消息降噪 / 卡片样式

以下选项随 `0.2.1-alpha.2.shell.1` 交付，旧安装包尚无这些控件。
在管理窗口编辑应用，或设置页展开高级配置，工作区之后可以选择。
当前源码候选版将管理窗口的「消息样式／降噪」独立于「已有应用（高级）」；扫码创建也能
直接找到这些选项。保存按钮不再藏在高级凭据区，保存后已开启的连接会按新设置重连：

| 选项 | 可选值 | 默认 |
|---|---|---|
| 消息详细度 | 完整（full）/ 精简（compact）/ 静默（quiet） | 精简 |
| 流式预览 | 开启或关闭 | 开启 |
| 刷新间隔 | 1.5s / 3s / 5s；已有合法非预设值会原样回显 | 3s（3000ms） |
| 卡片样式 | 经典（legacy）/ 富卡片（rich，Card 2.0） | 经典 |
| 进度展示 | 逐条（legacy）/ 单消息更新（compact）/ 结构化卡片（card） | 逐条 |

精简和静默不逐条发送思考/工具消息；静默将文本追加到同一卡片，仍保留最终答复、必要错误
与权限交互。进度展示和卡片样式是独立偏好，不承诺所有状态行或卡片按钮都会消失。
关闭流式预览不会关闭最终答复；间隔控件此时禁用，但保留已选值。

没有新字段的旧 `settings.json` 无需手改：读取时自动采用 compact、开启预览、3000ms、
legacy 卡片与 legacy 进度。合法整数间隔钳制到 500–30000ms；不接受自由文本 TOML。
配置生成一次全局 `[stream_preview]`、项目的 `[projects.display]`，固定预览增量为 80 字符。
显式保存过的偏好在旧调用/二维码参数省略这些字段时仍保留。

点击「保存应用／保存连接」后，已运行的启用连接会重新生成 TOML 并重启；未运行、已禁用或 Safe Mode
下保存不会隐式启动。轮询只更新状态，不覆盖未保存编辑；重开设置页会回显已保存值。
行为取舍见 [ADR 0036](decisions/0036-bounded-message-preferences.zh.md)。

「关闭连接」（旧设置页「停止」）会停止 Sidecar 并持久保存禁用；重启应用和退出 Safe Mode
后仍保持关闭。「启动 Desktop 时自动连接」独立控制下次启动，不能重新开启已关闭的连接；
新应用默认关闭自动连接，旧配置迁移保留原启动行为。手动「开启连接」不要求打开自动连接。
「重新连接」只重启已经启用的当前应用，不隐式解除关闭。未配置完整、Harness 尚未就绪、
工作区失效或 Safe Mode 时，Sidecar 不启动；保存另一份应用不改变当前连接。

## Safe Mode 行为

进入 Safe Mode 前，Desktop 会先停止 cc-connect，避免恢复期间仍有飞书消息进入任务。
退出 Safe Mode 并且 Harness 恢复就绪后，若连接配置仍启用，Desktop 会自动重启 cc-connect。
Safe Mode 不会删除 Secret、工作区或会话数据。

## 数据、凭证和日志位置

`<userData>` 是 Electron 的应用数据目录，常见位置如下；实际路径以系统和安装方式为准：

- macOS：`~/Library/Application Support/dsh-desktop`
- Linux：`~/.config/dsh-desktop`
- Windows：`%APPDATA%\\dsh-desktop`

连接相关文件位于 `<userData>/cc-connect/`：

- `applications.json`：版本化的本地应用列表、选中应用、启用意图和启动自动连接偏好，不含 Secret。
- `config.toml`：Sidecar 使用的固定配置，不含 Secret，只包含
  `${DSH_CC_CONNECT_FEISHU_SECRET}` 占位符。
- `credentials/<UUID>.json`：每份应用的私有凭据修订。macOS 新凭据使用本机受限明文文件，
  权限 `0600`；保存、读取和自动连接均不探测或调用 `safeStorage`，不访问系统钥匙串。
  文件权限不是加密，不能防同一账户运行的其它程序、管理员或读取备份的人。
  Windows 保留 Electron `safeStorage` / DPAPI；Linux 保留已有系统加密策略与文件回退。
  Windows 的 `0600` 不等同于 POSIX 用户隔离，文件回退需依赖所在目录的 Windows ACL。
  所有情况下 Secret 都不写入 TOML、renderer 状态或日志。
- `applications/<应用 UUID>/data/`：各新应用隔离的 cc-connect 运行数据。
- 旧 `settings.json` / `credentials.json` 会在首次读取时无损迁移，成功提交后才清理旧凭据；
  原应用继续使用 `data/`，不要求手改配置。macOS 历史 `safeStorage` 凭据仅复制密文、不解密，
  显示「请重新录入一次 App Secret」；连接不启动且不自动重试。旧密文保留到用户显式成功
  保存替换凭据后才清理；不在启动路径自动迁移，避免再触发系统授权。
  新 Secret 保存后可手动开启或按原自动连接偏好在下次启动连接。损坏文件失败关闭，不覆盖成默认值。

此变化仅移除飞书凭据在 macOS 上的钥匙串访问，不使用 `use-mock-keychain`，不修改签名、
系统钥匙串或浏览器 Cookie。当前 Electron Cookie Encryption fuse 为 disabled；不能仅凭
磁盘存在 Cookies 文件就认定还需要禁用另一条钥匙串路径。

`<userData>/logs/cc-connect.log` 是 Sidecar 的滚动日志，文件权限为 `0600`。Desktop
默认还会把 DSH_HOME 放在 `~/.dsh-desktop`；只有显式设置 `DSH_HOME` 时才会改用指定目录，
例如设置为 `~/.dsh` 就会与命令行共用 Harness 数据。cc-connect 和 Web Harness 是独立进程，
但默认使用同一个 Desktop DSH_HOME。

查看日志时可在「桌面工具 → 打开日志」打开日志目录，或直接查看上述 `cc-connect.log`。
状态卡片中的「最近错误」和日志中的凭证、Token 会做脱敏；分享诊断时仍应先检查工作区路径、
App ID 和会话标识，不要粘贴任何 Secret。

## 彻底禁用和删除凭证

1. 点击「关闭连接」，确认服务已关闭；该选择跨重启持久。
2. 在已保存应用卡片点击「移除本地配置」并确认。删除凭证与记录由主进程完成；若还在运行，
   先停止再移除，停止失败保留记录并提示重试，不误报成功。
3. 移除不删除远端飞书应用、工作区、DSH 会话或聊天运行数据。需要撤销远端应用时，另行
   点击「打开飞书应用管理」，按组织要求操作；Desktop 不会暗中撤销。

不需要手删凭据文件，也不应删除系统 `safeStorage` 服务密钥、整个 `<userData>` 或
`~/.dsh-desktop`。关闭管理窗口不关闭连接；关闭主窗口会退出 Desktop 并停止所有服务，
但不改写保存的自动连接意图。关闭连接、Safe Mode 暂停和移除本地配置仍是不同操作。

## 已知限制

- 可保存多份本地应用，但一次只有一个活动应用；每份仍只生成固定的 `dsh-desktop` 项目
  和一个 Feishu/Lark 平台，使用一个默认工作区；
  支持受控的消息降噪 / 卡片样式选项，不提供多项目/多平台、按聊天切换工作区或交互式模型选择。
- 首版只使用飞书长连接，不启用 cc-connect 的 bridge、management API 或 webhook 监听。
- 卡片按钮依赖飞书回调订阅和已发布权限；权限审批、可用范围和版本发布由飞书后台控制。
- 自动化测试使用假 Sidecar、临时目录和本地 ACP/HTTP mock，不代表真实飞书账号验收。首次
  实际连接仍需要用户自己的 App ID、App Secret 和组织审批。
- Sidecar 在 Harness 就绪后才启动，并有有限的崩溃重启预算；持续失败时请查看状态卡片和
  脱敏日志，修复配置后再点击「重连」。
