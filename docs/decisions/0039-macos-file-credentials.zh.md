# 0039：macOS 飞书凭据改用受限文件，不访问钥匙串

- 日期：2026-10-14
- 状态：已接受；仅在 macOS 上取代 ADR 0033 优先系统加密存储的规则。
- English：[0039](0039-macos-file-credentials.md)

当前 macOS 分发使用 ad-hoc 签名，指定要求含构建 cdhash，更新可能使旧钥匙串授权
失效。用户明确选择飞书 App Secret 不弹钥匙串、接受静态保护下降：macOS 保存
0600 明文凭据文件，连 safeStorage 可用性探测也不调用。Windows 保留 DPAPI；
Linux 保留原有策略。文件权限不是加密，不能阻止同一用户运行的其它程序或管理员；
Windows 的 POSIX 0600 也不能单独建立仅所有者可读的 ACL。

旧 macOS 加密文档保留并标记「需要重新录入 Secret」，启动、重连与恢复均不隐式
解密或迁移，不启动进程、不自动重试。用户显式成功保存后，经原有原子事务替换
旧修订。UI 区分未配置、旧凭据需重录、本机明文文件与系统保护凭据，不回传 Secret。

不改签名，不使用 mock keychain 或固定测试密码。只读检查已安装 Electron 二进制
确认 Cookie 加密关闭；Cookies 文件存在不是第二条钥匙串访问路径的证据。
仍需隔离冷启动与跨构建验收，不能靠源码断言或访问真实钥匙串替代。
