# 0037：统一飞书应用管理、持久连接意图与分层健康状态

- 日期：2026-10-11
- 状态：已接受
- English：[0037](0037-feishu-application-manager.md)

## 背景与决策

ADR 0033 原定仅在设置集成。已经交付的原生二维码菜单和用户要求的应用生命周期需要一个
可以回访的管理窗口，由设置与菜单共同打开。本决策只替代该入口限制，不改变权威、凭证
及单平台边界。DSH 仍是 Agent/会话权威；Desktop 拥有本地应用记录，并只监管一份选中
配置的 cc-connect Sidecar。

保存多份具名本地应用，各自保留工作区和 ADR 0036 消息偏好。凭证按记录隔离、受保护存储，
不进入应用列表、TOML、renderer 状态或诊断。重复 App ID 更新同一记录；保存另一份应用
不替换当前连接。切换串行执行：成功停止旧进程后，才能选中/启动另一份。移除须确认并先停
选中连接，只删除准确的本地记录/凭证，不删除远端飞书应用、工作区或 DSH 会话。

`enabled` 表示持久连接意图，`autoConnect` 仅控制 Desktop 启动时自动连接。显式关闭先保存
`enabled=false` 再停进程；停止失败须如实显示仍存活的进程/错误，不允许第二个进程启动。
关闭窗口不改连接意图，但取消尚未完成的扫码流程。Safe Mode 仅暂停，退出时若仍启用则
恢复，不受启动专用的 autoConnect 限制；退出应用也保留意图。旧启用配置迁移为自动连接，
凭证与全部显示偏好无损。保存、打开窗口和只读体检不发送测试消息，也不暗中切换应用。

默认二维码创建，支持过期、取消与重试；手填是高级备用路径。手机授权、收到凭据、受保护
保存、进程初始化、飞书通道在线、DSH 任务可用是不同事实。`cc-connect ready` 只证明进程
初始化；通道健康需要定义清楚的结构化事件，没有证据则显示待确认。DSH 错误（含缺模型
key）独立于机器人凭证，指向现有 Models/credentials 服务。只有用户主动发起的成功往返
才记录验证时间，不承诺永久可用。Lark CLI 用户 OAuth/skills 是另一条认证链路，不是
Desktop 扫码前提。

管理窗口使用独立受限 preload，只提供连接操作，并核对准确的 webContents、已加载页面
和顶层 frame；不放宽主 Harness IPC guard 或 CSP。设置卡片和原生菜单复用主进程控制器
及状态。

## 后果与备选

- 相比扩充单份表单，迁移及串行生命周期多一些成本，但避免保存覆盖应用、关闭后意外重连。
- 不把进程 ready 或任意日志文本当成“已连接”；待确认不如假成功方便，但不会宣称未经验证
  的消息与模型能力。
- 不做多机器人并发、多平台/项目路由、通用 management API 或自由 TOML。本地应用列表
  是配置管理，不是第二套 Agent 工作台。
- FS-01 记录契约；存储、生命周期、UI 必须经过 FS-02～FS-04 和 QA-01 才视为交付。
