# 交给低性能 Agent 的执行提示词

将下面提示词完整复制到新会话。只替换任务 ID 和本次明确授权；首次使用选择 **IT-00**。
不要使用“把所有计划做完”“自主连续迭代到发布”这类无范围指令。

```text
你在 dsh-desktop 仓库工作。本次只执行：IT-00。

计划入口：docs/plans/2026-10-19-agent-iteration/README.md
任务卡：docs/plans/2026-10-19-agent-iteration/tasks.md
进度：docs/plans/2026-10-19-agent-iteration/progress.md
事实盘点：docs/plans/2026-10-19-project-review.md

先读仓库 AGENTS.md、docs/README.md 与 CONTEXT.md，再读计划入口和本任务卡。
只读本任务必需的源码、ADR 和证据；不从头阅读所有历史计划，也不直接实施旧计划的 todo。

1. 检查当前分支、HEAD、未提交改动和 worktree。保留所有既有成果，不能 stash/reset/clean
   或覆盖别人的文件。正式实现前记录允许文件与本任务可验证目标。
2. 从 progress 确认前置条件与准入。waiting 只在依赖确实满足后领取；needs-review 必须先完成
   卡中指定的审查。证据任务只能调查，不能自行变成产品实现。
3. 检查本任务是否已被当前代码或另一个 worktree 做过。若已覆盖，交证据并建议结案，
   不为制造 diff 重写功能。遇到未定设计就记录最小选择，继续独立调查，交回审查。
4. 实现范围以卡为准。复用已有 API/状态/错误类型，避免通用框架、相邻重构或依赖升级。
   默认不超过 3 个产品/测试文件；超过必须重新拆卡。文档与证据按卡的允许范围维护。
5. 测试必须用隔离临时 profile、userData、workspace、假 key 和受控服务，不接管真实飞书，
   不发消息，不读真实凭据/会话，不改 /Applications。只清理本次拥有的进程和目录。
   旧 guarded E2E wrapper 含全局 pkill，IT-17/18 完成前不可在共享开发机直接运行它。
6. 按卡执行关联验证。首次失败保存完整输出，区分原有失败与本任务回归；最多两次同因修复
   没有新证据就停止扩大范围并报告。禁止跳过断言、放宽版本保护/覆盖率/资产契约、盲目延长超时。
7. 本轮初始 verify 有 locale watcher 失败，单跑通过不代表完整门禁通过。验证结果写实际命令、
   退出码、通过/失败/跳过数量、未覆盖平台。旧 CI、旧包和截图不能冒充本轮当前 SHA 的验证。
8. 保存 docs/plans/2026-10-19-agent-iteration/evidence/IT-xx.md 与 progress 回执。
   给出行为前后、文件、证据、未验证项和下一依赖。
   完成后结束本次任务，不领取下一卡，不默认 bump、推送、建 PR、改 issue 或发布。

现行关键约束：主窗口关闭退出；官方 WebUI 与 Agent 行为由上游负责；社区插件手动安装；
Dashboard 官方多版本 MVP 已实现、社区 Edition Adapter 未实现；L1–L3 不是 OS sandbox；
内核执行版本回退不是数据恢复。不得按旧文档恢复 close-to-tray 或静默安装社区软件。

本次授权范围：本任务卡列出的本地可逆操作、隔离验证与文档回执。
若本会话另有明确授权，以该授权为准；需要外部发消息、真实账户测试、发布或修改其他用户
工作成果时，先完成本地可审查产物，再交给有相应授权的会话执行。
```

## 调度者检查点

拿到回执后只核对五件事：范围是否符合、证据是否绑定本轮 SHA、用户路径是否实际验证、
失败与未覆盖是否如实列出、下一卡依赖是否真的满足。全部满足才更新调度状态。

遇到 C 类任务，交给能处理设计的 agent 先输出更小的已审查实现卡，再把小卡交给执行模型。
模型能力低时缩小任务，不降低产品断言；无法验证时明确交回，不把推测当完成。
