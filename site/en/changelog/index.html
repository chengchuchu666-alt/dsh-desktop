DSH Desktop Changelog

Versions are composite: <dsh kernel>.shell.<shell rev>. The kernel tracks the official @deepseek-ai/dsh package; shell revisions carry desktop-shell fixes and features only. Highlights below; full notes live on each GitHub release page.

v0.2.1-rc.2.shell.0 (kernel 0.2.1-rc.2)

  • Kernel upgrade 0.2.1-rc.1 → 0.2.1-rc.2: 32 @deepseek-ai/dsh-* peers re-synced, the manifest lockfile regenerated, release-age exemptions re-pinned (315 → 302 entries, 13 kept at the version resolved in the lockfile). Both reviewed shell patches are confirmed for the new kernel: the two patched upstream bundles are byte-identical between the kernels and the transforms still match, so the patch manifest now records the reviewed-kernel list explicitly.
  • macOS control-socket fix: the sidecar's per-application data directory pushed run/api.sock past the sun_path limit, so the manager reported a working connection as closed. The sidecar now gets a short $TMPDIR alias (a symlink to the real directory, no data migration): the 116-character path fails to bind where the 93-character alias succeeds, and a packaged run logs api server started socket=/var/folders/….
  • Rich Feishu cards by default for new connections (card style rich, progress display card); existing configurations and explicit legacy choices are untouched.
  • Linux arm64 packages: ubuntu-24.04-arm joined the release matrix and builds -arm64.deb from the same sources as amd64 (ten files in the GitHub Release, eight of them user-visible installers and checksums), and the in-app repair link follows the architecture it runs on.
  • Four-runner visual gate in the release flow: the macOS, Windows, Linux x64 and Linux arm64 runners must each render all 21 packaged extension surfaces (first-run and safe mode, the floating Feishu quick control, five Feishu manager states, six settings panes, LAN pairing, trash, recovery and loading) before a release publishes, and the screenshots ship as artifacts. Installation and desktop acceptance on real hardware or a VM stays a maintainer step (scripts/verify-visual-evidence.mjs).
  • Boundary note: all verification ran in isolated local or CI environments; health-check results are rendered locally in sanitized form and are never uploaded automatically.

v0.2.1-rc.1.shell.1 (kernel 0.2.1-rc.1)

  • Plugin crashes now self-heal (#115 family): a loader row that imports a package the bundled kernel does not carry used to leave only "startup failed" and a restart loop — Safe Mode could not help because it only collected rows inserted by user bundles, while the failing row usually comes from cordis.patch.yml or a file it includes. This release classifies that failure as missing-package, points the error page at the fix (update the app or disable the plugin), extends Safe Mode over the profile/home patch layers and their includes (user overrides of *official* rows stay enabled), and records non-bundle failing rows in a shell-owned quarantine overlay that skips them on the next start — reversible from the error page, the extensions menu, or by updating or disabling the plugin.
  • An unwritable profile no longer loops (#100/#116): the kernel rewrites profiles/web/cordis.yml on every start, so a read-only file (or an ACL/Controlled Folder Access block) used to look like "blank screen, then it never starts again" while the health check still reported the data folder as writable. The shell now probes the profile *files* before spawning, refuses to spin on a doomed boot, and shows a page with the concrete path and a one-click "repair file permissions and restart" action; the storage health check uses the same probe and the diagnostic report gained a profile_write= line.
  • Blank renderers are diagnosable (#100): renderer console errors/warnings and unresponsive events are captured into a bounded, redacted renderer_errors section of the diagnostic report, and the renderer-failure page now carries the first exception.
  • More complete diagnostics: the plugin inventory reports patch_layers and unkeyed_rows.
  • The bundled kernel is unchanged at @deepseek-ai/dsh 0.2.1-rc.1; only the shell revision moves, so upstream 0.2.1-rc.2 is deliberately not pulled in by a shell release.
  • Everything stays local-first: the diagnostic report is still generated on-device and never uploaded automatically, and the repair only clears the read-only attribute — it does not touch ACLs, security-software settings, or user data.

v0.2.1-rc.1.shell.0 (kernel 0.2.1-rc.1)

  • Kernel upgrade: the bundled Harness moves from alpha.5 to 0.2.1-rc.1 (upstream next channel) with 32 kernel-family direct dependencies, the lockfile and minimumReleaseAgeExclude re-synced; upstream published its preview notes at 2026-10-17T05:22Z.
  • Scope of those notes: they summarize the whole 0.2.1 line since v0.2.0-rc.2, most of which already reached this shell in alpha.1–alpha.5. For the alpha.5 → rc.1 step, per-package registry metadata shows 297 kernel packages changed only in version strings, and the surfaces this shell actually uses (session controller, workspace client, account patch, ACP composition) are unchanged in rc.1.
  • Closure diff: all 297 kernel packages shrink by 100–500 bytes each from the 0.2.1-alpha.5 → 0.2.1-rc.1 substitution with no dependency added or removed; of the three packages this shell patches or depends on by contract, dsh-api-session-controller and dsh-client-ui-workspace are byte-identical, dsh-client-ui-settings-account differs only in two version strings, and the ACP/headless cordis.patch.yml composition is unchanged.
  • Removed or changed upstream interfaces audited: rc.1 drops the runtime invariant plugin and each package's ./invariant export, the both tool-display mode and the input-area stats row, turns --from-default-profile into a replace-style rebuild, and delivers Agent Team messages straight to the Inbox. A repository-wide search confirms this shell uses none of them (no from-default-profile call, no invariant reference, no stats row, no both mode), and its ACP and credential boundaries still match the existing assertions.
  • Plugin framework promoted: the cordis family the kernel declares moved from -alpha.2 prereleases to stable releases in the same batch (@deepseek-ai/cordis 4.0.5, cordis-plugin-include 1.0.10, cordis-plugin-loader 1.0.6, cordis-plugin-timer 1.1.7, plus same-line cosmokit/schemastery updates); those stable releases predate rc.1, so this is the kernel's own resolution rather than a dependency this shell added.
  • Account-login compatibility: the account patch moved to rc.1 unchanged and still uses the embedded login only when the official desktop bridge exposes dshOnboarding.hasApiKey; when Electron refuses a pre-opened blank window it hands the real authorization URL to the system browser once, without opening up navigation, Node privileges or external protocols.
  • Trash compatibility: the session controller and workspace client are byte-identical to alpha.5 and the version guard now targets rc.1 after re-checking the anchors; running, queued, cross-client-owned, maintenance and child sessions still refuse deletion.
  • Reproducible builds: pnpm run bootstrap now always generates and validates the lockfile with the repository-pinned pnpm 10.33.2 and explicitly requests the hoisted layout instead of inheriting the caller's pnpm environment; the compact patchedDependencies form written by pnpm 11 is rejected by 10.33.2 as a configuration mismatch and used to abort bootstrap with ERR_PNPM_LOCKFILE_CONFIG_MISMATCH.
  • Feishu quick control: the floating panel's Connect group keeps application, desktop process, Feishu channel and DSH-task states separate with explicit start, stop and reconnect; opening or polling it is read-only and never connects, sends a message or calls a model.

v0.2.1-alpha.5.shell.0 (kernel 0.2.1-alpha.5)

  • Upgrades the bundled Harness to the published 0.2.1-alpha.5 preview and resyncs the exact closure lockfile.
  • Extends the release-age exemptions from the real lockfile resolution, with a pure regression test that keeps peer-suffixed keys from becoming bogus package pins.
  • Carries the reviewed account patch to alpha.5, preserving system-browser authorization and the official-desktop-only login capability check.
  • Verifies the session-trash lifecycle anchors against the new upstream bundles before updating the version guard; busy, owned, maintenance and child sessions remain protected.
  • Keeps the ACP saved-credential composition and the separation between Feishu secrets and model API keys.
  • Adds a floating Feishu quick control that shows the selected application, desktop process, Feishu channel and DSH verification separately, with explicit start/stop/reconnect; opening it never connects, sends a message or calls a model, and missing applications, legacy credentials or Safe Mode disable the actions.
  • Verified with 438 unit tests plus ACP, both packaged smokes, 24 packaged E2E cases, 25 repeated Feishu cases, market offline/real and packaged LAN pairing. The gated tag pipeline still owns the three-platform build/upgrade/provenance checks; live phone Feishu round trips and manual Windows/Linux native review are outside local evidence.

v0.2.1-alpha.3.shell.0 (kernel 0.2.1-alpha.3)

  • Upgrades to Harness 0.2.1-alpha.3, with version-bound Desktop login and session-trash compatibility.
  • Keeps system-browser authorization, busy-session and ownership protections, and the ACP saved-credential composition.
  • Adds Feishu entries to the main settings list and floating Desktop tools menu, separates message styles from manual credentials, and fixes edge-positioned menus, long application names and standalone button contrast.
  • UI review, both local packaged smokes, all 24 packaged cases and 25 repeated Feishu checks passed.
  • macOS, Windows and Linux build/install/upgrade gates passed, with 24 packaged cases on each platform.
  • The existing Linux worker teardown warning remains; Windows installation timing was 7.94% slower than the fixed older baseline.
  • Published installers must also pass the gated tag pipeline. Live Feishu delivery and manual native-control review on Windows/Linux are outside this validation.

v0.2.1-alpha.2.shell.4 (kernel 0.2.1-alpha.2)

  • Closing the main window now exits the application and stops its owned services. Minimize/start-hidden activation remains supported; closing the Feishu manager alone does not close a saved connection.
  • Terminal shutdown preempts pending connection startup and attempts every independent service stop; repeated quit requests cannot bypass cleanup. Saved connection intent is preserved.
  • macOS Feishu Secrets use owner-restricted plaintext files instead of Keychain access. Legacy encrypted Secrets are retained without background decryption and require one explicit re-entry. Windows DPAPI and Linux policies remain unchanged; no mock-keychain, cookie, or signing bypass is introduced.
  • Removes modern declaration files from the bundled runtime while preserving executable and native resources. Three alternating pre-release Windows trials improved median installation time by 4.9% on that runner only; this is not a speed guarantee for every PC.
  • Keeps Harness 0.2.1-alpha.2 and the cc-connect pin unchanged. Fresh versioned packages and all release gates are required, with isolated credentials, verified mirrors and published-only website changelogs.

v0.2.1-alpha.2.shell.3 (kernel 0.2.1-alpha.2)

  • Updates Electron to 44.7.0 and YAML to 2.9.1; applies reviewed proxy-addr, compression and MCP SDK repairs while keeping Harness 0.2.1-alpha.2 and preserving the optional SDK functionality.
  • Updates electron-builder to 26.17.0 without downgrading the reviewed plist/xmldom resolutions. Node declarations remain on 24, aligned with runtime rather than accepting a Node 26 major bump.
  • Adds bilingual Feishu setup, noise/card settings, connection lifecycle and credential boundaries to the website, with Keychain and Windows profile-permission guidance. Issue #100 is not claimed fixed.
  • Regenerates site commits from latest main on push races, handles changelog-only changes, and keeps future drafts out of the published changelog. Isolated regressions and eight website UI scenarios pass.
  • Waits for final reply and turn-lock release in the file-attachment CUJ before temporary-directory cleanup; 200 race repetitions pass without changing the production Agent or Feishu behavior.
  • Existing sprintf-js and ad-hoc-signing limitations remain documented. SDK updates do not silently migrate or revoke old OAuth credentials; follow issuer/re-authentication guidance where applicable.

v0.2.1-alpha.2.shell.2 (kernel 0.2.1-alpha.2)

  • Styles the Feishu management entry consistently and separates connection health text from the button, preserving Secret storage, connection intent and Safe Mode behavior.
  • Fixes the localized LAN QR countdown without changing expiry, one-time pairing or sharing permissions.
  • Uses cross-platform content dimensions in UI regression and drains separate mock sessions before cleanup. Local unit, ACP, Go/race and candidate packaged gates passed without weakened assertions.
  • The final installed shell.2 passed visual review, a real Feishu reply, and automatic QR decoding into an isolated mobile browser, including session access, rotation, reload, single-use pairing and logout. This is not physical-camera or separate-device Wi-Fi evidence. Temporary sharing is disabled afterward.
  • macOS remains ad-hoc signed; signature changes can require Keychain authorization despite saved encrypted credentials. Stable distribution signing is a separate follow-up, not a plaintext-credential workaround.
