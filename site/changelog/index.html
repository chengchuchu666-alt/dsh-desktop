DSH Desktop 更新日志

版本号是复合形式 <dsh 内核版本>.shell.<壳修订>：内核随官方 @deepseek-ai/dsh 升级，壳修订只包含桌面壳自身的修复与功能。以下节选近期版本要点，完整说明见各版本 Release 页。

v0.2.1-rc.1.shell.0 （内核 0.2.1-rc.1）

  • 内核升级：把内置 Harness 从 alpha.5 升到上游 next 通道的 0.2.1-rc.1，同步 32 个 内核同族直接依赖、锁文件与 minimumReleaseAgeExclude。上游目前只发布了 npm 包 （dist-tag next），尚未发布对应的 GitHub Release 或变更说明，因此本节不引用未公开的发布文案。
  • 闭包差异：按 registry 元数据逐包比对，297 个内核包全部只有版本字符串一类的小幅缩减 （每个包 −100～−500 字节，来自 0.2.1-alpha.5 → 0.2.1-rc.1 的替换），没有新增或移除依赖； 壳直接打补丁或依赖契约的三个包中，dsh-api-session-controller 与 dsh-client-ui-workspace 逐字节一致，dsh-client-ui-settings-account 仅两处版本字符串变化，ACP/headless 的 cordis.patch.yml 组合未变。
  • 插件框架转正：内核声明的 cordis 家族在同一批次由 -alpha.2 预发布转为稳定版 （@deepseek-ai/cordis 4.0.5、cordis-plugin-include 1.0.10、cordis-plugin-loader 1.0.6、 cordis-plugin-timer 1.1.7，以及 cosmokit/schemastery 同线更新），稳定版发布时间早于 rc.1，属于内核自身声明的范围解析结果，不是本壳额外引入的依赖。
  • 账户登录兼容：账户补丁随精确版本迁移到 rc.1，补丁内容不变，继续只在官方桌面桥具备 dshOnboarding.hasApiKey 能力时走内嵌登录；Electron 拒绝预开空白窗口时仍把实际授权 URL 一次性交给系统浏览器，不放开导航、Node 权限或外链协议。
  • 垃圾桶兼容：会话控制器与工作区客户端与 alpha.5 逐字节一致，补丁锚点重新核对后版本保护 更新为 rc.1；运行中、排队中、跨客户端所有权、维护中及子会话仍拒绝删除。
  • 构建可复现性：pnpm run bootstrap 现在固定使用仓库锁定的 pnpm 10.33.2 生成/校验锁文件， 并显式请求 hoisted 布局，不再依赖外层 pnpm 注入的环境；此前用 pnpm 11 写出的紧凑 patchedDependencies 形式会被 10.33.2 判为配置不匹配，导致 bootstrap 在 ERR_PNPM_LOCKFILE_CONFIG_MISMATCH 处中止。
  • 飞书快捷控制：浮窗「连接」分组继续分开显示当前应用、桌面进程、飞书通道与 DSH 任务， 并提供显式开启、关闭、重连；打开或轮询只读，不隐式连接、不发消息、不调用模型。

v0.2.1-alpha.5.shell.0 （内核 0.2.1-alpha.5）

  • 内核升级：升级到官方已发布的 alpha.5 预览版，同步内核同族直接依赖与完整锁文件闭包。 上游包含已打开会话的 / 技能列表随插件启停刷新、批量新建/恢复终端时减少重复查询、 Windows/Linux 右侧栏收起时输入框 Page Up 不再左移界面、PTC 指引与模型身份说明统一， 并新增 conversation.input.model.label Slot。
  • 供应链豁免按真实闭包补齐：新内核首次引入的传递依赖同样处于 24 小时发布窗口内； sync-release-age-excludes.mjs 现按新锁文件实际解析结果补齐 minimumReleaseAgeExclude， 纯函数回归覆盖 peer 后缀解析，避免把 peer 依赖误写成包名或让冻结安装反复失败。
  • 桌面登录兼容：账户补丁随精确版本迁移到 alpha.5，继续只在官方桌面桥具备 dshOnboarding.hasApiKey 能力时走内嵌登录；Electron 拒绝预开空白窗口时， 仍把实际授权 URL 一次性交给系统浏览器，不放开导航、Node 权限或外链协议。
  • 垃圾桶兼容：alpha.3 → alpha.5 的上游会话控制器与工作区客户端逐字节一致， 补丁锚点已重新核对，版本保护更新为 alpha.5；运行中、排队中、跨客户端所有权、 维护中及子会话仍拒绝删除。
  • 飞书凭据边界：ACP 组合仍加载 Models 已保存的模型凭据， headless 专用的凭据覆盖不会套用到机器人连接；飞书 App Secret 与模型 API Key 保持分离。
  • 飞书快捷控制：桌面工具浮窗的「连接」分组新增当前应用、桌面进程、飞书通道与 DSH 任务 四行只读状态，并提供显式开启、关闭、重连。打开浮窗或读取状态不会隐式连接、发消息或调用模型； 没有应用、旧凭据需重录、Safe Mode 时按钮禁用并说明原因，关闭连接仍持久保存禁用。

v0.2.1-alpha.3.shell.0 （内核 0.2.1-alpha.3）

  • 内核升级：升级到官方已发布的 alpha.3，同步依赖闭包与兼容补丁；历史 shell.4 tag 保持不可变。
  • 桌面登录兼容：适配新版登录预开窗口流程，继续把实际授权页面交给系统浏览器， 避免壳的同名桥被误判为官方桌面组合；不放开桌面窗口的导航、Node 权限或外链协议限制。
  • 垃圾桶兼容：适配新内核会话创建/串行化入口，保留运行中、排队中、跨客户端所有权与子会话保护。
  • 飞书凭据边界：核对 ACP 仍加载 Models 已保存的模型凭据，不将 headless 专用凭据策略套到机器人连接。 飞书 App Secret 与模型 API Key 仍分离，不新增凭据导出或系统钥匙串访问。
  • 飞书更容易找到：设置主列表、桌面工具展开菜单新增入口；原有入口保留并复用同一个管理窗口。
  • 消息样式独立入口：降噪与卡片选项不再藏在手动凭据区；保存按钮常显，长应用名不会撑出窗口。
  • 界面边缘修正：浮窗菜单按可用空间展开并滚动，缩窗保持入口可达，Escape 返回焦点； 独立窗口主按钮改善亮暗主题文字对比度。

v0.2.1-alpha.2.shell.4 （内核 0.2.1-alpha.2）

  • 关闭即退出：关闭主窗口现在会退出整个应用，停止 Harness、飞书连接和局域网服务， 不再留在后台。最小化/隐藏启动后仍可用快捷键或托盘唤回；关闭飞书管理小窗口只关闭界面。
  • 退出收尾可靠性：修复连接还在启动时退出会留下 Sidecar 的边界；独立服务并行停止， 单项失败不跳过其余清理，重复退出请求不会抢先绕过清理。连接意图与自动连接选择保留。
  • macOS 飞书不再访问钥匙串：新 Secret 保存到主进程管理的本机受限文件（权限 0600）， 保存、读取及自动连接都不调用系统安全存储。旧加密 Secret 保留但不后台解密， 设置页提示重新填写一次，保存成功后才替换；不再每次更新反复请求钥匙串访问。
  • Windows 安装精简与计时：补删不参与运行的 .d.mts / .d.cts 声明文件，维护候选本地闭包 减少1464个文件（约7.7 MB）；保留可执行文件、原生模块、资源及许可证。 同一 Windows runner 三轮安装中位数165.7→157.6秒，改善约4.9%；这是发布前维护候选的 对照结果，不承诺所有电脑同样提速，也不把累计安装阶段冒称纯解压时间。
  • 安全边界：macOS 受限文件是明文，不是加密保险箱；同用户程序、管理员和可读取备份者 仍可能访问。Windows 保留原 DPAPI 策略，Linux 保留原存储策略。不改系统钥匙串、Cookie 或签名策略，不加入 use-mock-keychain。macOS 分发仍为 ad-hoc 签名。

v0.2.1-alpha.2.shell.3 （内核 0.2.1-alpha.2）

  • 运行时与安全维护：Electron 44.7.0、YAML 2.9.1；捆绑闭包更新 proxy-addr 2.0.8、 compression 1.8.2 与 MCP SDK 1.31.0。显式保留原有可选 SDK 功能，不用移除包来消除告警， 不升级 Harness 内核或无关 Web 栈。
  • 打包依赖审查：electron-builder 26.17.0，保留既有 macOS 工具的 plist 3.1.1 / xmldom 0.9.12，避免依赖 PR 的额外降级；Node 类型继续与 Node 24 运行时一致，不采用 Node 26 类型。
  • 官网与飞书指南：中英首页新增独立飞书连接流程，说明工作区、精简消息、卡片、连接意图、 安全模式与组织权限。FAQ 区分机器人 Secret、模型 Key 和 CLI OAuth，补充 Keychain 与 Windows profile 写入权限排查；不把最初白屏问题冒称为已修复。
  • 官网同步可靠性：生成文件 push 冲突时基于最新主干重新生成并限次重试；只变更新日志时 也会提交。官网日志以已发布 tag 为上界，不提前展示未来版本草稿。
  • 测试收尾可靠性：cc-connect 文件附件 CUJ 等到最终回复且任务锁释放后才结束， 修复后台持久化与临时目录清理的竞争；不改变 Agent 或飞书生产行为。

v0.2.1-alpha.2.shell.2 （内核 0.2.1-alpha.2）

  • 飞书设置布局：管理应用/扫码创建入口复用桌面设置按钮样式，健康说明独立成块； 窄卡片与中英文界面不再将入口和状态文字混排。不改变 Secret 存储、连接意图或 Safe Mode。
  • 局域网配对倒计时：二维码窗口正确逐秒更新剩余时间，不再一直显示 600 秒； 真实到期时间、一次性配对和手动关闭共享规则不变。
  • 发布回归稳定性：窗口宽度断言按内容尺寸跨平台验证；cc-connect 测试使用独立 会话事件通道并等待最终回复后清理临时目录，不跳过或降低原行为断言。

v0.2.1-alpha.2.shell.1 （内核 0.2.1-alpha.2）

  • 垃圾桶与侧栏同步：删除、还原和取消归档后无需重启；活动任务、驻留子任务、身份冲突及其他进程持有的会话会被安全拒绝，不强停或覆盖。
  • 完整飞书应用管理：设置和原生菜单打开同一独立窗口；默认扫码创建，支持取消、过期重试、多份本地应用、编辑、开启、持久关闭和确认移除。扫码保存不隐式开启或切换，关闭窗口不关闭连接。
  • 消息降噪与卡片：默认精简 + 3 秒预览；可选完整/精简/静默、流式预览、经典/富卡片和进度样式。修复 ACP 思考被重复映射成正文的问题；旧配置和凭据无损迁移。
  • 可靠状态与安全边界：捆绑 cc-connect 提供真实长连接健康信号，分别显示服务启动、飞书通道在线和 DSH 实际任务成功；缺模型 key 指向 Models。Secret 不回读、不进入 TOML/日志；Safe Mode 暂停和持久关闭保持独立。

v0.2.1-alpha.2.shell.0 （内核 0.2.1-alpha.2）

  • 飞书消息连接：从原生「扩展 / Desktop tools」菜单打开独立二维码配置窗口，完成回调后由受监督的 cc-connect Sidecar 将飞书消息接入 DSH；设置页支持启动、停止、重连和 Safe Mode 生命周期。
  • 一键 CLI 与 skills：新增 pnpm run feishu:setup，调用官方 Lark CLI 完成用户 OAuth，并可安装官方 lark-* skills；用户 CLI 身份与 cc-connect 机器人身份明确分离。
  • 运行时与可靠性：升级内置 DSH 到 0.2.1-alpha.2，同步 32 个 peer pin，并按新内核重建登录自动打开补丁；新增多运行时管理面板及更严格的运行时路径校验。
  • 安全边界：二维码配置使用临时目录，Secret 只进入受保护凭证存储或权限为 0600 的文件，不写入日志、仓库或普通设置文件。
